I think you have identified an interesting opportunity here, because what you're describing is not simply a website redesign. It's a brand experience redesign.

You're noticing a disconnect between two experiences:

- The physical experience: You visit Kaldan Samudhra, experience its architecture, hospitality, grand scale, atmosphere and attention to detail.
- The digital experience: You visit its website, but the website doesn't necessarily communicate that same feeling before someone books.

That's an important distinction. A luxury hotel's website shouldn't just tell you that the property is luxurious. It should make you feel that luxury before you've even considered making a reservation.

And your references make sense. You're gravitating towards a particular design philosophy:

- Cinematic imagery rather than conventional hotel photography.
- Minimalist typography with confident, oversized headlines.
- Intentional whitespace.
- Storytelling instead of immediately presenting booking controls.
- A few beautifully executed scroll interactions rather than dozens of distracting animations.
- A restrained colour palette that complements the actual property.
- Smooth transitions that make navigating the website feel like moving through a physical space.

I would approach this as a combination of UX audit, luxury hospitality brand positioning, frontend prototyping and conversion optimisation.

And yes, I can examine the websites and their publicly accessible visual references. I can understand screenshots, images, layouts, typography and design compositions. I can also inspect accessible website code and structure. There is one limitation: I cannot automatically experience every animation exactly as a human browsing the live website would, so screen recordings or screenshots of specific interactions can help me analyse those more accurately.

Let's start by examining the actual websites before deciding what to build.

I would not automatically install everything.

For this prototype, GSAP + ScrollTrigger and CSS transitions are probably enough.

Also, don't sacrifice performance for animation. Optimised video, responsive images, lazy loading, mobile-specific video assets, reduced-motion support and sensible animation durations are essential.

A beautiful luxury website that takes eight seconds to load is not a luxury experience.

## 6. Should you inspect the existing website code yourself?

Absolutely. But don't immediately start copying the entire website.

I would make this your next task.

Your goal is to understand what the existing website is built with, what can be reused, and what should be redesigned.

Here's the process I'd follow.

### Step 1: Inspect the website in Chrome DevTools

Open the website on your laptop.

Press:

`F12` or `Ctrl + Shift + I`

Explore these tabs:

| Tab | What to investigate |
| --- | --- |
| Elements | HTML structure and DOM hierarchy |
| Styles | CSS rules, typography, colours and spacing |
| Network | Images, videos, fonts and external scripts |
| Sources | Publicly available frontend resources |
| Performance | Rendering bottlenecks and loading behaviour |
| Lighthouse | Performance, accessibility, SEO and best practices |

Pay special attention to the Network tab.

Filter by:

- `Img`
- `Media`
- `Font`
- `CSS`
- `JS`

You may discover that the website already has high-quality photography, but the way it is being displayed is underwhelming.

Or perhaps the hero video really is compressed, improperly sized or poorly encoded.

Don't assume the cause until you've inspected it.

### Step 2: Identify the technology stack

You should figure out:

- Is it WordPress?
- Is it a custom React application?
- Is it built with another CMS?
- Is it using a booking engine?
- Which external scripts are responsible for reservations?
- Where are the images and videos hosted?

Useful tools:

- [BuiltWith](<https://builtwith.com/?utm_source=chatgpt.com>) — Technology detection.
- [Wappalyzer](<https://www.wappalyzer.com/?utm_source=chatgpt.com>) — CMS and framework detection.
- [PageSpeed Insights](<https://pagespeed.web.dev/?utm_source=chatgpt.com>) — Performance analysis.
- [Chrome DevTools documentation](<https://developer.chrome.com/docs/devtools/?utm_source=chatgpt.com>) — Frontend inspection.

### Step 3: Create a website audit document

Before touching any code, document the current website.

I'd create a spreadsheet with these columns:

| Page | Existing problem | Proposed improvement | Priority |
| --- | --- | --- | --- |
| Homepage | Weak first impression | Cinematic hero | High |
| Homepage | Insufficient storytelling | Editorial introduction | High |
| Accommodation | Product-like presentation | Immersive room showcase | High |
| Experiences | Too much emphasis on individual facilities | Visual experience storytelling | Medium |
| Navigation | Lacks visual refinement | Minimal floating navigation | Medium |
| Enquiry | Limited lead capture opportunities | Dedicated enquiry CTA | High |

Include screenshots of each section.

This becomes your evidence when presenting your proposal.

Important: Publicly accessible frontend code is not the same as the website's complete source code. You cannot retrieve its private backend, CMS configuration, database, booking logic or proprietary assets just by inspecting a browser. Don't try to bypass access restrictions. You can build an independent prototype without any of those.
